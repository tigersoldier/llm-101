# 2.2 子词与相邻对合并（BPE）

2.1 把两个问题摆在了桌面上：英文样例有 24 个字符级编号，超过上下文 16；中文样例的 7 个字全部变成 `<unk>`。字符级切分让序列变长；词级切分让词表变大，而且在遇到没见过的词时只能退回 `<unk>`。这一节走中间路线：从单个字符出发，反复把语料中最常见的两个连续符号合并成一个新符号，用“常见片段”而不是整词或单字来做 token。

这条路线的名字是 BPE（Byte Pair Encoding，字节对编码）。本节实现三个函数：`count_pairs`、`merge_pair` 和 `learn_merges`；它们只处理字符串符号，不分配编号，也不建立词表。编号和词表留给 2.3。

## 子词与 BPE

先比较三种切分单位。

- **字符级**：一个字符一个 token。词表小，任何由已知字符组成的文本都能表示；代价是序列长。2.1 的固定样例 `the cat sat on the mat` 就是 22 个字符，也就是 22 个字符级 token。
- **词级**：一个整词一个 token。序列短，但词表通常有几万到几十万个词；没见过的词只能变成 `<unk>`，中文还没有空格可以直接切词。
- **子词**：把常见的字符片段当作一个 token，例如 `the`、`ing`、`小猫`、`坐在`。词表比词级小，序列比字符级短；没见过的词还可以拆成更小的片段。

BPE 属于子词（subword，也译作子词单元）方法。它最早用于数据压缩（Philip Gage，1994）：反复把最常见的相邻字节对替换成一个新符号，让数据变短。Sennrich、Haddow、Birch 在 2016 年把这个想法用于神经机器翻译的子词切分：从字符开始，按语料统计合并，得到一份可复用的词表。

本章实现的是**码点级** BPE：初始符号是 Unicode 码点（code point，Unicode 给每个字符的编号），不是字节。Python 的 `str` 按码点迭代，所以 `list("low")` 直接得到三个初始符号。它也**不做** GPT tokenizer 的正则预切分和空白符特殊处理。这样做的直接后果是，空格也是一个普通符号，合并可以跨过空格；下面的实际结果会看到 `the cat ` 这样的片段。这不是程序的错误，而是“没有单词边界”的码点级 BPE 的自然结果。字节级 BPE（从字节而不是码点开始合并）只放在扩展阅读里解释，本章不实现。

这里的“训练”是统计合并：没有参数、没有损失、没有反向传播，不会更新任何模型权重；第 6 章才是用梯度训练模型。

## 符号与相邻对

BPE 的第一步是把文本看成符号序列。初始时每个符号是一个码点，也就是 Python 字符串里的一个字符：

```text
"low"  ->  ['l', 'o', 'w']
```

合并之后，一个符号可以是多个字符组成的字符串，例如 `lo`、`low`、`lowe`。所以后文的“符号”不再等于“单个字符”；它可以是任意长度的片段。

相邻对（adjacent pair）是序列里两个连续符号组成的有序对。对 `['l', 'o', 'w']`，相邻对是 `('l', 'o')` 和 `('o', 'w')`；`count_pairs` 统计所有序列里这些对出现的次数。

统计只在同一条序列内部进行：`["ab", "cd"]` 不会产生 `('b', 'c')`，因为两条序列之间没有相邻关系。这个边界很重要；如果跨序列统计，合并会学到不存在的连接。

### `count_pairs`

`count_pairs` 的用途是给训练循环提供每轮的候选对。

输入是若干条符号序列（`Iterable[Sequence[str]]`）；输出是 `Counter[Pair]`，键是有序对 `(left, right)`，值是出现次数。`Pair` 是 `tuple[str, str]` 的类型别名；`Counter` 是 `collections` 里的计数容器，键是元素，值是出现次数。

用 `low` 和 `lower` 两条序列：

```text
>>> count_pairs([["l", "o", "w"], ["l", "o", "w", "e", "r"]])
Counter({('l', 'o'): 2, ('o', 'w'): 2, ('w', 'e'): 1, ('e', 'r'): 1})
```

```python
def count_pairs(sequences: Iterable[Sequence[str]]) -> Counter[Pair]:
    # 遍历每条序列，统计相邻的两个符号
    ...
```

实现时用 `pairwise` 逐条累加即可。`pairwise` 是 `itertools` 里的库函数：接收一个可迭代对象，依次给出相邻两项组成的对；例如 `pairwise(['l', 'o', 'w'])` 得到 `('l', 'o')` 和 `('o', 'w')`。这样不需要把序列拼起来。

### `merge_pair`

`merge_pair` 执行一次合并：在一条符号序列里找出指定的相邻对，把它们替换成一个新符号。

输入是符号序列 `Sequence[str]` 和要合并的 `Pair`；输出是新的 `list[str]`，不修改输入。

合并规则是**从左到右、不重叠**：遇到匹配就合成一个符号，然后跳过这两个符号。这样 `['a', 'a', 'a']` 合并 `('a', 'a')` 得到 `['aa', 'a']`，而不是 `['a', 'aa']`；`['a', 'a', 'a', 'a']` 得到 `['aa', 'aa']`。

```text
>>> merge_pair(["l", "o", "w"], ("l", "o"))
['lo', 'w']
>>> merge_pair(["a", "a", "a"], ("a", "a"))
['aa', 'a']
>>> merge_pair(["a", "a", "a", "a"], ("a", "a"))
['aa', 'aa']
>>> merge_pair(["a", "b", "a", "b"], ("a", "b"))
['ab', 'ab']
>>> merge_pair(["a", "b"], ("b", "a"))
['a', 'b']
```

```python
def merge_pair(symbols: Sequence[str], pair: Pair) -> list[str]:
    # 从左到右扫描；命中 pair 就合成一个符号并跳两步
    ...
```

非重叠规则让一次合并的结果是确定的；否则 `['a', 'a', 'a']` 既可以变成 `['aa', 'a']`，也可以变成 `['a', 'aa']`。

## 从一对到合并列表

`learn_merges` 把“统计、选对、合并”重复起来，返回一个有序的合并列表。这个列表的顺序就是后面编码时要重放的顺序。合并列表里的位置叫合并顺序（merge rank，秩）；下文的图和表把它简写为 rank，从 0 开始编号。

每一轮做四件事：

1. 统计当前所有序列的相邻对；
2. 选频率最高的对；频率相同按 `(left, right)` 的字典序选，保证同一语料每次得到同一个结果；
3. 在所有序列上合并这一对；
4. 检查停止条件：达到 `num_merges`、最高频率低于 `min_frequency`，或已经没有相邻对。

用 `low`、`lower`、`lowest` 走一遍，`min_frequency=1` 时得到 6 条合并。表中的 `l o` 表示相邻对 `('l', 'o')`；其他写法同理，中间的空格只是分隔两个符号：

|轮次|候选对（频率）|选中|合并后的三条序列|
|---|---|---|---|
|0|`l o` 3，`o w` 3，`w e` 2，`e r` 1，`e s` 1，`s t` 1|`l o`|`lo w`；`lo w e r`；`lo w e s t`|
|1|`lo w` 3，`w e` 2，`e r` 1，`e s` 1，`s t` 1|`lo w`|`low`；`low e r`；`low e s t`|
|2|`low e` 2，`e r` 1，`e s` 1，`s t` 1|`low e`|`low`；`lowe r`；`lowe s t`|
|3|`lowe r` 1，`lowe s` 1，`s t` 1|`lowe r`|`low`；`lower`；`lowe s t`|
|4|`lowe s` 1，`s t` 1|`lowe s`|`low`；`lower`；`lowes t`|
|5|`lowes t` 1|`lowes t`|`low`；`lower`；`lowest`|

第 0 轮 `l o` 和 `o w` 都是 3 次，按字典序选 `('l','o')`；第 3 轮三个候选都是 1 次，按字典序选 `('lowe','r')`。这就是“同一份语料得到同一个合并列表”的具体含义。所以 `learn_merges(["low", "lower", "lowest"], 6, min_frequency=1)` 返回 `[('l', 'o'), ('lo', 'w'), ('low', 'e'), ('lowe', 'r'), ('lowe', 's'), ('lowes', 't')]`。

如果把 `min_frequency` 设为 2，第 3 轮（rank 3）的最高频率是 1，低于阈值，循环在 rank 2 结束后停止，只得到前 3 条合并。`num_merges=0` 时循环一次也不执行，返回空列表；但如果没有任何非空文本，函数仍会先报 `ValueError`；`num_merges` 为负数或 `min_frequency` 小于 1 时也会报 `ValueError`。

朴素实现每轮重新统计所有序列：合并 $M$ 次、总符号数为 $N$ 时，工作量约 $O(MN)$。本章演示语料很小，不做额外的加速；真实语料上的采样和加速留到第 7 章。

## 参考实现

三个函数都在 `ch02/end/src/llm101/tokenizer.py` 里。`Pair` 是 `tuple[str, str]` 的类型别名，三个函数都使用它。

```python
from collections import Counter
from collections.abc import Iterable, Sequence
from itertools import pairwise

Pair = tuple[str, str]


def merge_pair(symbols: Sequence[str], pair: Pair) -> list[str]:
    """Merge non-overlapping occurrences of ``pair`` from left to right."""
    left, right = pair
    merged: list[str] = []
    index = 0
    while index < len(symbols):
        if (
            index + 1 < len(symbols)
            and symbols[index] == left
            and symbols[index + 1] == right
        ):
            merged.append(left + right)
            index += 2
        else:
            merged.append(symbols[index])
            index += 1
    return merged


def count_pairs(sequences: Iterable[Sequence[str]]) -> Counter[Pair]:
    """Count adjacent symbol pairs within each sequence."""
    counts: Counter[Pair] = Counter()
    for sequence in sequences:
        counts.update(pairwise(sequence))
    return counts


def learn_merges(
    texts: Iterable[str],
    num_merges: int,
    *,
    min_frequency: int = 2,
) -> list[Pair]:
    """Learn up to ``num_merges`` pairs, most frequent first.

    Ties are broken by the lexicographic order of ``(left, right)``, so the
    same corpus always produces the same merge list.
    """
    if num_merges < 0:
        raise ValueError("num_merges must be non-negative")
    if min_frequency < 1:
        raise ValueError("min_frequency must be positive")

    sequences = [list(text) for text in texts]
    if not sequences or not any(sequences):
        raise ValueError("cannot learn merges without non-empty texts")

    merges: list[Pair] = []
    for _ in range(num_merges):
        counts = count_pairs(sequences)
        if not counts:
            break
        best_pair, frequency = min(
            counts.items(),
            key=lambda item: (-item[1], item[0]),
        )
        if frequency < min_frequency:
            break
        merges.append(best_pair)
        sequences = [merge_pair(sequence, best_pair) for sequence in sequences]
    return merges
```

三个函数都不分配编号；`learn_merges` 的返回值也只是字符串对，不是词表。2.3 会把观察到的码点、特殊 token 和这些合并结果按顺序排成词表。

## 扩展阅读：BPE 从哪里来，子词为什么是折中

BPE 最早不是为语言模型设计的。1994 年，Philip Gage 在数据压缩里提出“反复替换最常见的相邻字节对”：把最高频的两个字节换成一个新字节，重复到没有明显收益为止。这是“Byte Pair Encoding”这个名字的来历；它关心的是文件更小，不是语言单位。

2016 年，Sennrich、Haddow 和 Birch 把这个替换过程搬到神经机器翻译：先把文本按空格或正则切成词，再在每个词内部从字符开始合并，得到 `low`、`lower`、`lowest` 这类子词。例如在词 `lower` 内部，先合并 `l` + `o` 得到 `lo w e r`，再合并 `lo` + `w` 得到 `low e r`；记录下来的替换顺序就是编码规则。这样词表不必包含所有整词，没见过的词也能拆成常见片段。原始用法仍然有“词”这个前置边界；本章为了看清合并本身，直接在整条文本的码点上操作，所以空格也可能被合并进去。

字节级 BPE（byte-level BPE）把初始符号从码点换成字节。UTF-8 把每个码点写成 1–4 个字节；汉字 `猫` 是一个码点，在 UTF-8 里是三个字节 `E7 8C AB`，所以字节级 BPE 一开始把它看成三个符号，而不是一个。这样初始词表只需要 256 个字节值，任何 UTF-8 文本都能表示，不会出现 `<unk>`；代价是一个汉字要占多个符号，合并必须先学会跨字节组合。本章用码点级 BPE，是为了让中文样例的符号数和汉字数对得上；GPT-2 和之后的 GPT 模型使用字节级 BPE，2.4 会再说明码点和字节的区别。

和相邻方法比：

- **BPE**：按相邻对频率合并，合并顺序就是编码规则；实现简单，结果确定。
- **WordPiece**：也合并片段，但选择标准是让整份语料出现的概率提升最多，常见于 BERT 一类模型。
- **Unigram**：先准备一个较大的候选词表，再按概率删减，最后得到子词表；和 BPE 的方向相反。

三种方法都在“词表大小”和“序列长度”之间取折中。字符级词表小、序列长；词级序列短、词表大且 OOV 多；子词把常见片段收进词表，让常见词只占一个 token，同时保留拆开生词的能力。
