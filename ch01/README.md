# 第 1 章 看得见的 transformer

第 1 章把完整但很小的 decoder-only transformer 一次搭起来，只做前向，并用一个 Python web server 把每一层的输入输出显示在浏览器里。后续章节在这批模块上继续加东西：第 2 章换 tokenizer，第 3 章加手写梯度，第 5 章放大到最终维度。

整体规划见仓库根目录 `PLAN.md`，全书写作风格见 `STYLE.md`；第 1 章的概念引入时机调整见 `PLAN.md` 第 13 节。

## 写作流程

每节按同一节奏进行：

1. 读 `sections/<编号>.md` 的“目标 / 内容安排 / 验收”。
2. 正文写到 `docs/course/ch01/<编号>.md`（第 1.1 节顺带创建 `docs/course/ch01/index.md` 与 `mkdocs.yml` 的子导航）。
3. 代码在 `ch01/end/` 里实现。**1.1 时先把 `ch01/start/` 整体复制到 `ch01/end/`**，之后只改 `end/`；`start/` 保持脚手架原样，便于对照“本章要填什么”。
4. 跑该节“验收”里列出的测试或命令；新增测试放 `ch01/end/tests/`。
5. 把 `sections/<编号>.md` 的“状态：待写”改成“状态：完成”，并在本文件的进度清单里打勾。
6. 全章写完后，`ch01/end/` 即为第 2 章 `start/` 的来源。

**术语顺序**：正文只使用本节或更早小节已经介绍过的术语，专业术语第一次出现不得早于介绍并实现它的那一章。需要提前提到后续内容时，用通俗语言说明并指出“第 X 节会讲”，不要只丢一个名词。小节清单和导航可以提前列出标题，那是路线图；正文不能假定读者已经认识它们。

**术语译名**：术语第一次出现时附中文译名，有多种通用译法的全部列出（如 tokenizer：分词器、标记器、词元切分器）；没有公认译名的不强译（如 transformer）；缩写与符号第一次出现时写出完整单词。每节新增的术语补进 `docs/glossary.md`，并链接回本节。

**图解与数学**：每个概念和计算配一张 SVG 图（结构与数据流），正文给至少一组输入/输出例子；数学补充只写大学及以上的内容，大学之前的数学不解释，没有就不写这一节。

**类型注解**：正文和示例里的 Python 代码必须带完整参数与返回注解（含 `-> None`），示例与真实代码一致；`tests/test_docs_examples.py` 检查 `docs/**/*.md` 的 Python 代码块。

**概念与扩展阅读**：概念在最早需要它的章节引入，先说明本质（如 tensor 是多维数组）；有新概念的章节在末尾加“扩展阅读”，讲动机和没有它的代价。

**函数结构**：每节按概念小节组织，函数在自己的概念小节里给用法、输入输出、输入输出样例和带注释的签名（不用表格）；再给参考实现；最后给每个函数的实际结果（能用公式/图表达的，先矩阵/张量公式，再代数式/逐元素展开）。复杂实现按 `STYLE.md` 先写编号步骤、最小例子和中间结果，再配矩阵或多阶段图。

**螺旋编排**：第 1 章每节都用固定示例 `the cat sat`，节末给出本节结束后的管线输出（1.1/1.2 是编号、答案和字符，1.3 起是编号和数字）与本节架构图；只画当时已有的步骤，后续组件在对应小节才出现。详见 `PLAN.md` 第 12 节。

**小节导航**：上一节/下一节由 MkDocs Material 的 `navigation.footer` 按 `mkdocs.yml` 的导航顺序自动生成；小节页面里不写链接，也不单独维护小节顺序。

## 本章不做什么

- 不实现反向传播、不训练、不读真实语料；权重是固定 seed 的随机初始化。
- 不做 BPE（第 2 章）、不放大维度（第 5 章）、不做 KV cache（后续章节）。
- 前端不引入构建工具和第三方库。
