# 2.3 训练词表：语料、特殊 token 与目标大小

- 状态：待写
- 预计篇幅：约 3800 字，代码 5 处，图 2 张
- 前置：2.2

## 目标

- 理解词表由三部分组成：特殊 token、初始码点、合并产生的新符号；会算 $|V| = |S| + |A| + M$，其中 $M$ 是合并新增的 token 数。
- 能造一份英中教学语料：自写、许可明确、固定示例各出现至少 3 次，供第 2–6 章使用。
- 能写出 `BPETokenizer.train`：收集字母表、校验目标大小、算合并次数、调用 `learn_merges`、按固定顺序建词表。
- 知道特殊 token 的顺序与 id：`<unk>` 0、`<bos>` 1、`<eos>` 2；知道为什么本章不加 `<pad>`。
- 能说清目标 512 与实际词表大小的关系：`min_frequency` 可能提前停止，实际值由语料决定。
- 能用 `vocabulary`、`vocab_size`、`unk_id`、`bos_id`、`eos_id` 检查词表，不依赖“固定 512”这个数字。

## 内容安排

1. 问题：2.2 只有符号串和合并列表，没有编号；模型要整数 id，且要能区分未知字符、序列开头和结尾。
2. 词表的组成：特殊 token（3 个）→ 初始码点（语料中出现的不同字符，按字典序）→ 合并结果（按合并顺序追加）。每个 token 的 id 就是它在这个序列里的位置。写出公式
   $$|V| = |S| + |A| + |M|$$
   并给最小计算：`low`/`lower`/`lowest` 的字母表是 7 个码点，特殊 token 3 个，目标 12 时合并次数是 $12-3-7=2$，词表正好 12。$M$ 指“合并新增的 token 数”；如果某次合并得到的字符串已经在词表里，它不会让词表变大，所以 $M$ 可能小于合并次数。实现要按字符串去重，正文用实际值。
3. 特殊 token：`<unk>`（unknown，未知词元）、`<bos>`（beginning of sequence，序列开头）、`<eos>`（end of sequence，序列结尾）的全称与作用；本章不加 `<pad>`，因为还没有补齐序列的需求；等真正实现 padding 时再加，避免提前引入。特殊 token 放在最前面，id 分别是 0、1、2。
4. 教学语料：`samples/english.txt`、`samples/chinese.txt`；各约 200 行，合计约 13,000–20,000 个字符（实际统计记录在 `samples/README.md`）；主题限定在动物、家庭、天气、日常动作；全部自写，随仓库文字采用 CC BY 4.0；不下载、不嵌入任何外部数据集原文。固定示例 `the cat sat on the mat` 和 `小猫坐在垫子上` 各整行出现至少 3 次，保证合并能覆盖示例中的高频片段。`samples/README.md` 记录行数、字符数、许可和“固定示例出现次数”。
5. 语料边界：一行一句，UTF-8、LF 换行、无空行；不包含 `<unk>`/`<bos>`/`<eos>` 的拼写，也不包含 NUL；这些由 `tests/test_samples.py` 检查。留出句放 `samples/heldout_english.txt`、`samples/heldout_chinese.txt`，只给 2.5 评估用，不参与训练。
6. `BPETokenizer.__init__` 的输入与校验：`initial_tokens`、`merges`、`special_tokens`；重复 token、空 token、合并引用未知 token、合并结果与特殊 token 同名都要报错；特殊 token 必须包含 `<unk>`/`<bos>`/`<eos>`，本章只用这三个，不加 `<pad>`。说明为什么要在构造时校验，而不是等到 `encode` 才失败。
7. `BPETokenizer.train` 的编号步骤：
   1. 把 `texts` 转成 `list[str]`，避免生成器只能读一次；
   2. 收集所有非空文本的码点，按字典序排序，得到 $A$；
   3. 校验 `vocab_size >= |S| + A`，否则报错并给出最小词表；
   4. 算 `num_merges = vocab_size - |S| - A`；
   5. 调用 `learn_merges(texts, num_merges, min_frequency=...)`；
   6. 用 `initial_tokens`、`merges`、`special_tokens` 构造对象；词表大小可能小于 `vocab_size`。
8. 参考实现：`__init__`、`train`、`vocabulary`、`vocab_size`、`unk_id`、`bos_id`、`eos_id`；每个都给用法、输入输出、样例和带注释的签名。用 `vocab_size=12` 的例子写出完整词表：
   `("<unk>", "<bos>", "<eos>", "e", "l", "o", "r", "s", "t", "w", "lo", "low")`，并给出每个 token 的 id。
9. 实际结果：在教学语料上训练目标 512；打印实际 `vocab_size`、$A$、$M$、前 10 条合并、前 10 个词表条目；英文/中文固定样例的 ids 与 token 数。如果实际值小于 512，说明是 `min_frequency=2` 提前停止，不硬凑。
10. 图：`06-vocabulary-layers.svg`（特殊 token / 初始码点 / 合并结果三层堆叠，标出实际大小）、`07-vocab-growth.svg`（合并次数与词表大小的折线，标出目标 512 和实际停止点）。

## 验收

- `uv run pytest tests/test_tokenizer.py -q -k "train or vocab or special"` 通过；新增测试覆盖：
  - `test_vocabulary_order_and_ids`：`vocab_size=12` 的例子得到 12 个 token，前三个是 `<unk>`/`<bos>`/`<eos>`，`unk_id=0`、`bos_id=1`、`eos_id=2`，后两个是 `lo`/`low`；
  - `test_train_rejects_small_vocab_size`：目标 9 报错，错误信息含 `at least 10`；
  - `test_train_merge_count_matches_target`：在 `low`/`lower`/`lowest` 上，目标 12 得到 2 条合并，目标 13 得到 3 条合并（默认 `min_frequency=2`）；
  - `test_train_stops_at_min_frequency`：小语料上目标 512、`min_frequency=2` 时实际词表小于 512，且停止原因是最高频率低于 2；
  - `test_train_rejects_duplicate_special_tokens`：重复的特殊 token 报错；
  - `test_duplicate_merge_result`：两次合并得到同一个字符串时词表只增加一次；初始 token 为 `("a","b","c")`、合并为 `(("a","b"),("b","c"),("ab","c"),("a","bc"))` 时 `vocab_size` 是 9（3 个特殊 token + 3 个初始 token + `ab`、`bc`、`abc`），而合并列表长度是 4。
- `uv run pytest tests/test_samples.py -q` 通过：行数、字符数、UTF-8、无特殊 token 拼写、无 NUL、固定示例各出现至少 3 次。
- `uv run python scripts/show_tokenizer.py --stage 3` 打印实际 `vocab_size`、$A$、$M$、前 10 条词表与两条固定样例的 ids。
- `vocab_size == 3 + A + M`，其中 `M` 是合并新增的 token 数；`vocab_size <= 3 + A + len(merges)`；`3 + A <= vocab_size <= 512`；`vocab_size == len(vocabulary)`。
- `samples/README.md` 记录行数、字符数、许可和固定示例次数。

## 写作注意

- 第一次出现“训练 tokenizer”时明确：这是统计合并，没有参数、没有损失、没有反向传播；模型训练在第 6 章。不要把“训练”写成梯度更新。
- 词表顺序必须写死并在正文、代码、测试中一致：特殊 token（按 `special_tokens` 给定顺序）→ 初始码点（字典序）→ 合并结果（合并顺序）。id 由这个顺序决定。
- `bos_id`/`eos_id` 的数值会从第 1 章的 66/67 变成 1/2；这是 tokenizer 自己的编号变化，五个接口的含义不变。正文要说明这一点，不要让读者以为模型接口变了。
- 不在本节讲 `encode`/`decode` 的实现；只用 `vocabulary` 和 id 检查词表。编码/解码留在 2.4。
- 不加 `<pad>`；不引入 `initial_alphabet`、`max_texts` 之类第 7 章才需要的参数。
- 教学语料是自写教学数据，不声称代表真实语言分布；第 7 章才接 TinyStories。语料行数和字符数用实际统计值，不写“约 500 条”这种没有核对过的数字。
- 如果实际词表小于 512，正文要给出实际值、$A$、$M$ 和停止原因；不要为了凑 512 修改语料或降低 `min_frequency` 到 1。
- 目标 512 的设定要说明理由：比第 1 章的 68 大得多、能覆盖常见片段，又小到可以在 CPU 上快速训练和检查；8192 的理由留到第 7 章。
- 本节不写“数学补充”：词表加法、字典序和阈值比较不需要大学数学。
