# 2.5 中英混合与词表评估

- 状态：待写
- 预计篇幅：约 3200 字，代码 3 处，图 3 张
- 前置：2.4

## 目标

- 理解联合词表：一份词表同时覆盖英文和中文，不按语言分表，也不加语言控制 token。
- 会算字符数 $N$、token 数 $T$、压缩率 $R = N / T$、`<unk>` 数与 OOV 率，并能给一条句子的完整手算。
- 能跑 `scripts/tokenizer_report.py`，对两条固定样例和留出句给出表格：字符数、token 数、压缩率、`<unk>` 数。
- 能解释英文和中文压缩率不同的原因，以及 token 数对上下文窗口和训练成本的影响。
- 知道词表大小、压缩率、覆盖率之间的取舍；知道本章只观察，不调参（第 7 章才做真实语料配比）。

## 内容安排

1. 问题：2.4 只验证了单句往返；现在要知道这份词表在英文/中文上到底省了多少 token、漏了多少字，以及两条固定样例之外的表现。
2. 联合词表：一份词表、两种语言；特殊 token 共用；英文有空格，中文没有空格；码点级 BPE 的初始单位对两种语言都是码点。给出联合词表的示意：同一个 id 在英文和中文里含义相同，不按语言切换。
3. 指标定义：
   - 字符数 $N$：`len(text)`，按 Unicode 码点计数，包含空格和标点；
   - token 数 $T$：`len(tokenizer.encode(text))`，不含 `<bos>`/`<eos>`；
   - 压缩率 $R = N / T$：一个 token 平均覆盖多少个码点；
   - `<unk>` 数：编码结果中 `unk_id` 的个数；OOV 率 $= \text{unk 数} / N$。
   每个公式给一个最小计算例子：迷你 tokenizer 上 `"lower"` 是 5 个码点、3 个 token，$R = 5/3 \approx 1.67$；`"lowx"` 是 4 个码点、2 个 token，`<unk>` 1 个，OOV 率 0.25。
4. 指标函数：`token_count`、`compression_ratio`、`unknown_count` 的用法、输入输出、样例、带注释的签名和参考实现；放在 `src/llm101/tokenizer.py`，因为它们只依赖 tokenizer，后续统计 token 数也会用到。
5. `scripts/tokenizer_report.py`：`ReportRow`、`build_report`、`format_table`、`main` 的分工；读 `samples/english.txt`、`samples/chinese.txt` 的固定样例和 `samples/heldout_*.txt` 的留出句；输出表格的列：标签、字符数、token 数、压缩率、`<unk>` 数。
6. 实际报告：英文样例、中文样例、英文留出句 2 条、中文留出句 2 条；英文样例和中文样例是同一句话的英中对应，压缩率可以直接对照。表格给出实际数字；解释英文压缩率通常高于中文的原因：英文有空格和常见字母组合，能合并成长片段；中文一个汉字本身就是一个码点、文字密度高，合并空间较小。
7. OOV：留出句里放一个训练语料没有的生僻字，`unknown_count > 0`；`decode` 会丢掉该字；讨论“扩大字母表”和“增加合并”的取舍：前者让词表变大、后者对未见过字符无效。给一个具体句子和它的 `<unk>` 位置。
8. 语言配比：教学语料英文/中文行数接近，但字符数不同；合并统计会偏向出现次数更多的一侧。这里只观察并记录，不调整配比；第 7 章才按 token 预算而不是行数配比。
9. 图：`12-compression.svg`（英文/中文的压缩率分组柱状图，标出实际值）、`13-oov.svg`（留出句的已知 token 与 `<unk>` 构成）、`14-tokenizer-eval.svg`（扩展阅读：指标与取舍）。
10. 扩展阅读：tokenizer 评估的常见指标（压缩率、覆盖率、fertility、序列长度）、多语言词表公平性、为什么 token 数直接影响上下文和成本；`14-tokenizer-eval.svg`。

## 验收

- `uv run pytest tests/test_report.py -q` 通过；新增测试覆盖：
  - `test_token_count_excludes_specials`：`token_count(tokenizer, "lower") == 3`，与 `len(encode("lower"))` 一致；
  - `test_compression_ratio_hand_example`：迷你 tokenizer 上 `"lower"` 的压缩率约为 1.67，`"low"` 等于 3.0；
  - `test_unknown_count`：`"lowx"` 的 `<unk>` 数为 1，`"low"` 为 0；
  - `test_compression_ratio_rejects_empty_text`：空文本报 `ValueError`；
  - `test_report_rows_match_encode`：报告里每一行的 token 数都等于 `len(encode(text))`，`<unk>` 数都等于编码结果中的 `unk_id` 个数。
- `uv run python scripts/tokenizer_report.py` 输出表格，包含英文/中文固定样例与留出句。
- 手算至少一条留出句的字符数、token 数、压缩率，与脚本结果一致（压缩率误差小于 0.01）。
- 留出句里至少有一条 `unknown_count > 0`；`decode` 后该字消失，报告能指出这一点。
- `samples/README.md` 列出训练文件与留出文件，并说明留出文件不参与训练。

## 写作注意

- 指标定义要写清是否包含空格、标点、`<bos>`/`<eos>`：本章统一“字符数包含空格和标点，token 数不含特殊 token”。
- 不把“中文压缩率低”说成缺点或优点；它反映码点级切分与文字密度，正文只讨论对上下文窗口和训练成本的影响。
- 不在本章调词表大小、`min_frequency` 或语料配比；这些留给第 7 章的真实语料预算。这里只记录观察结果。
- 图表数值必须来自实际运行；不要手写假数据，也不要把预期范围写进正文。
- `token_count`/`compression_ratio`/`unknown_count` 是新增的库函数，要按函数结构写用法、输入输出、样例和签名；不要让读者只看到脚本输出。
- `build_report` 的输入是 `(标签, 文本)` 序列，输出是 `ReportRow` 列表；`format_table` 只负责排版，不重新编码文本。
- 扩展阅读按科普文章写：指标起源、原始用法/样例、定义与对比、解释、图例；不要变成“如何调 tokenizer”的清单。
